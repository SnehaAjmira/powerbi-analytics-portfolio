# Project Saguaro: Battery Cell Gigafactory Project Analytics from Six Data Sources

An end-to-end analytics build for a fictional greenfield lithium-ion battery cell gigafactory delivered from design through construction and turnover. The cell manufacturing building has electrode, dry-room assembly and formation and aging areas, plus a central utility building, NMP solvent recovery plant, electrolyte storage, wastewater treatment and substation.

Like a real project, the data sits in **six different systems**. The work here is to connect to each one, translate their different column names and ID formats into one model, check that the keys line up, and report across engineering, procurement, construction, completions, safety and quality.

> All data is synthetic. "Contoso Energy", "Project Saguaro" and every company, document, tag and number are generated by [`generate_gigafactory_data.py`](../data-generator/generate_gigafactory_data.py).

## Source systems

| Source | Connector | Tables | What makes it realistic |
|---|---|---|---|
| **SQL Server** engineering database `SaguaroPIIM` | `Sql.Database` (query folding) | Reference data, document revisions, RFIs, submittals | Schemas (`ref`, `eng`, `rpt`), primary and foreign keys, reporting views |
| **ERP** purchase order export | `Excel.Workbook` | PO lines | ERP column names, line items in steps of 10, **ERP vendor numbers that must be mapped to project company IDs** through a cross-reference table in SQL |
| **P6** schedule / progress export | `Excel.Workbook` | Work packages, weekly planned / earned / actual hours | P6-style headers ("Budgeted Units", "Earned Units") |
| **Completions system** | `Folder.Files` + `Csv.Document` | ITRs (22 monthly extract files), tag register, punch list | New extract files are picked up automatically; overlapping extracts are de-duplicated |
| **HSE web API** | `Json.Document` (offline copy; `Web.Contents` ready) | Weekly manhours and incidents | OData-style `value` array, camelCase fields |
| **SharePoint list** | `Excel.Workbook` (offline copy; `SharePoint.Tables` ready) | NCR log | SharePoint system columns (ID, Created, Modified, Path) removed |

## Build steps

**1. Set up the database.** Install SQL Server Express (free) and SSMS. Copy the data package to `C:\PowerBI\gigafactory\`. In SSMS, run `sql_server\01_create_database.sql`, then `02_load_data.sql`, then `03_reporting_views.sql`. If `BULK INSERT` returns "access denied", the SQL Server service account cannot read your folder. Either give it read access or load each CSV with **Tasks > Import Flat File**.

**2. Connect Power BI.** Create three text parameters: `SqlServer` (for example `localhost\SQLEXPRESS`), `SqlDatabase` = `SaguaroPIIM`, and `SourceRoot` = `C:\PowerBI\gigafactory\`. Add each query from [powerquery/all_sources.m](powerquery/all_sources.m) as a blank query with the same name. Turn off load for `company_erp_xref`.

**3. Model.** Create the relationships in [model/relationships.md](model/relationships.md). Add [dax/01_tables_and_columns.dax](dax/01_tables_and_columns.dax), then paste [dax/02_measures.dax](dax/02_measures.dax) into DAX query view and click **Update model with changes**.

**4. Report pages.**
1. Executive overview: KPI cards with status colors (IFC %, earned vs planned %, SPI, CPI, open RFIs, value at risk, ITR A %, punch A open, TRIR)
2. Engineering: IFC planned vs actual S-curve, variance by discipline, review backlog, first-pass approval
3. RFIs & submittals: open RFI trend, aging buckets, overdue by subcontractor and area, submittal approval and turnaround
4. Procurement: ROS vs forecast, float distribution, value at risk by supplier, open long-lead items
5. Construction progress: planned / earned / actual hours S-curve, weekly SPI, SPI and CPI heatmap by area and discipline
6. Completions & turnover: MC and turnover S-curves, ITR A/B by system, punch burndown, subsystem readiness
7. Safety & quality: rolling 12-month TRIR, near-miss ratio, NCRs by category and root cause
8. Data quality: row counts per source, last refresh, unmapped vendors, orphan keys

**5. Save as `.pbip`** into this folder so the model and report are tracked as text.

## Skills shown

Connecting to and integrating SQL Server, Excel, CSV folders, JSON APIs and SharePoint; T-SQL DDL, keys, views, CTEs and window functions; Power Query renaming, type handling, merges through a cross-reference table and folder combines; star schema design without ambiguous filter paths; DAX for S-curves capped at a status date, as-of backlog counts, earned value and OSHA incident rates; Python (pandas) for cross-source data quality checks and KPI reporting.
